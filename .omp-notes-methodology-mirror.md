# Design note: remove methodology auto-maintain of todo list

Status: DECIDED (pending implementation) — 2026-08-24

## Problem

The pentest flow tracks phases via the `methodology` tool (source of truth,
persisted to `methodology.json`). The methodology tool auto-mirrors phase
transitions into the session todo list via `mirrorTodoStatuses`
(`packages/coding-agent/src/tools/methodology.ts:48-80`). This mirror:

1. Updates session todo memory (`setTodoPhases`) and persists
   (`appendCustomEntry(USER_TODO_EDIT_CUSTOM_TYPE, {phases})`)
2. But NEVER notifies the UI panel — `event-controller.ts:1646` gates the UI
   refresh on `event.toolName === "todo"`, and methodology results arrive as
   `toolName === "write"` (xd-device dispatch via `write xd://methodology`)
3. So the TUI todo panel shows a stale snapshot (stuck at early phase) while
   the data is actually correct

## Why the mirror is unnecessary

- pentest.md step 3 ALREADY instructs the agent: `todo start <phase>` /
  `todo done <phase>` (direct todo calls)
- methodology.json is the real phase source of truth (compaction-proof)
- The todo list is purely a UI checklist; nothing downstream reads the
  mirrored todo for logic
- The mirror is a second source of truth that can diverge, adds 30 lines,
  and its only consumer (the UI) isn't even updated by it

## Fix (when implemented)

1. `methodology.ts`: delete `mirrorTodoStatuses` + its call sites in
   status/start/complete; remove the `TodoPhase`/`USER_TODO_EDIT_CUSTOM_TYPE`
   import
2. `pentest.md`: remove "auto-maintains the todo list (start/complete mirror,
   status reconciles)" from rules; make step 3 authoritative — mandate the
   agent calls `todo start/done` after every `methodology start/complete`
   (same phase name)
3. The UI-staleness bug disappears because direct `todo` tool calls have the
   proper UI notification path
